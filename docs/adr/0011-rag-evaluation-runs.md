# ADR 0011：版本化评测集与异步 RAG 评测运行

- 状态：已接受
- 日期：2026-07-26

## 背景

V2.6A 已提供仓库内严格 JSON 评测集和确定性指标，但尚不能保存真实 Dify 参数、逐题命中、运行状态或历史对比。V2.6B 需要在不污染业务知识库、不让 HTTP 请求等待 Cloud 检索、也不把供应商响应格式泄漏到领域层的前提下执行真实基线。

## 方案比较

1. 单个脚本输出 JSON/Markdown：实现最简单，但运行历史、并发、失败恢复和 Web 查询能力弱。
2. 单表保存运行并把全部逐题结果放入 JSONB：表少，但失败问题分页、约束和后续对比查询困难。
3. 仓库评测集 + 运行表 + 逐题结果表：实现成本较高，但输入可复现、结果可查询，并能复用 Outbox/Celery 可靠执行。

选择方案 3。`rag_evaluation_runs` 保存输入版本、哈希、参数、状态和汇总指标，`rag_evaluation_results` 每个问题一行。仓库 JSON 仍是评测集事实来源，PostgreSQL 不复制或允许在线编辑评测集。

## 决策

1. 使用独立 Dify Dataset 发布固定评测语料，业务 Dataset ID 保持不变。
2. API 创建运行和 `rag.evaluation.run` Outbox 消息位于同一事务；Worker 通过严格消息 Schema 接收运行 UUID。
3. 运行采用至少一次语义。Redis 短期锁避免并发重复执行，数据库唯一约束和逐次重建结果保证重投安全。
4. 每次运行保存评测集 ID、版本、SHA-256、可用的构建 revision、供应商、Dataset ID、split、TopK 和阈值。
5. 逐题结果保存文档级命中与确定性指标，不保存完整检索片段正文或密钥。
6. calibration 可用于调参；test 请求必须显式确认，防止调用方无意反复查看保留集。
7. 固定语料通过开发脚本幂等发布。Dify 索引是可重建派生数据，不新增本地语料镜像表。

## 结果与边界

- API、Worker 和 Dify 暂时不可用不会让已接受的评测运行消失。
- 相同幂等键和相同参数返回既有运行；相同键但参数不同返回冲突。
- 运行错误按脱敏错误代码持久化，供应商正文不入库。
- 第一版只提供 API 和基线报告，不在本阶段实现 Web 编辑器或 LLM-as-a-Judge。
- 独立 Dataset 仍需显式初始化语料；数据版本升级时重新运行发布脚本。
