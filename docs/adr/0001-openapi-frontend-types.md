# ADR 0001：使用 OpenAPI 生成前端类型

- 状态：已接受
- 日期：2026-07-18

## 背景

V1.2 增加告警管理 Web。若前端手写接口类型，后端 Schema 变化后容易产生静默漂移；直接强制安装与 TypeScript 7 不兼容的生成器则会隐藏依赖风险。

## 备选方案

1. 手写 TypeScript 类型：依赖少，但需要人工保持两份契约一致，长期风险最高。
2. 忽略 peer dependency 或强制安装：短期可运行，但升级、CI 和供应链行为不可预测。
3. 固定兼容版本并生成：多一步生成流程，但契约可审查、可复现，也便于未来自动化漂移检查。

## 决策

选择方案 3。后端以 FastAPI OpenAPI 为唯一 API 契约来源，提交确定性的 `openapi/openapi.json`；前端使用精确版本的 `@hey-api/openapi-ts` 生成 TypeScript 类型。由于生成器当前不兼容 TypeScript 7，前端将编译期依赖固定为 TypeScript 6.0.3，不使用 `--force` 或 `--legacy-peer-deps`。

## 影响

- 后端契约变化必须重新导出 OpenAPI、生成前端类型并运行测试。
- 生成目录只作为产物使用，不接受手工编辑。
- TypeScript 降级不改变浏览器运行时或 API 运行时，只影响编译和类型生成工具链。
- 当生成器明确支持 TypeScript 7 后，先在独立依赖升级中验证类型生成、类型检查、测试和构建，再解除版本固定。
