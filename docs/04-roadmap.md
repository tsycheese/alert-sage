# 开发路线图

## 1. 里程碑概览

| 版本 | 目标 | 可演示结果 |
| --- | --- | --- |
| V0 | 工程骨架 | API、Web、数据库可一键启动 |
| V1 | 核心闭环 | 告警从创建到人工确认、案例沉淀 |
| V2 | 求职展示版 | 恢复、幂等、降级、监控和 RAG 评测 |
| V3 | 扩展版 | 真实外部系统适配、告警聚合和权限 |

项目主要交付目标为 V2。

## 2. V0：工程骨架

- 创建 FastAPI、React 和 PostgreSQL 基础工程。
- 添加 Docker Compose 和 `.env.example`。
- 配置 SQLAlchemy、Alembic 和首个数据库迁移。
- 实现健康检查与前后端连通。
- 建立 pytest、前端测试和代码质量检查。

完成标准：新环境可以用一组明确命令启动，健康检查通过。

## 3. V1：完整业务闭环

### 3.1 告警管理

状态：V1.2 已完成 API、Web 页面、统一错误协议和 OpenAPI 类型生成链路。

- 实现告警创建、列表和详情接口。
- 使用数据库唯一约束实现幂等。
- 完成告警列表、详情和创建页面。

### 3.2 LangGraph 工作流

- 建立工作流 State 与七个核心节点。
- 实现四个模拟上下文工具。
- 使用结构化模型输出生成报告。
- 使用 PostgreSQL Checkpointer。
- 实现 `interrupt` 与批准、驳回、重新分析。

### 3.3 异步执行和页面事件

- 引入 Celery 与 Redis。
- API 投递启动/恢复任务，Worker 执行 LangGraph。
- 节点事件写入 `workflow_events`。
- 使用 SSE 推送页面状态。

### 3.4 案例沉淀

- 批准后生成结构化案例。
- 案例同步状态可查询、失败可重试。

完成标准：CPU 告警可以在 3 至 5 分钟内完整演示，且人工等待期间重启服务后仍可恢复。

## 4. V2：求职展示增强

### 4.1 可靠性

- 工具级超时、重试、熔断和部分失败降级。
- 工具调用幂等键和结果复用。
- 工作流失败重试及异常页面。
- 使用事务性 Outbox 补强数据库与任务投递一致性。
- 增加故障注入测试：Dify 超时、模型限流、Redis 重启、Worker 中断。

### 4.2 RAG

- 接入 Dify Knowledge Base API。
- 构建包含标准问题、相关文档和期望引用的评测集。
- 增加 pgvector 检索实现。
- 对比分段策略、TopK、混合检索和 rerank。
- 输出 Recall@K、引用命中率、回答正确率和延迟报告。

### 4.3 可观测性

- Prometheus 暴露 API、节点、工具、LLM 和 RAG 指标。
- Grafana 提供核心 Dashboard。
- 所有日志包含请求、告警、运行和线程关联 ID。
- 增加一次完整诊断链路的可视化时间线。

### 4.4 测试和文档

- 节点单元测试、数据库集成测试、恢复测试。
- Playwright 覆盖创建告警、等待确认和批准流程。
- 添加演示数据、架构图、运行截图和演示脚本。
- 记录关键技术决策及性能数据。

## 5. V3：可选扩展

- 接入真实 Prometheus HTTP API。
- 接入 Loki/Elasticsearch 日志搜索适配器。
- 接入真实 CMDB。
- 飞书机器人及告警卡片。
- 基于 fingerprint 和时间窗口的告警聚合。
- 只读自动化工具及细粒度审批策略。
- 用户认证与 RBAC。

## 6. 推荐实现顺序

严格按以下顺序推进，避免中间件阻塞核心价值验证：

1. PostgreSQL 数据模型和告警 CRUD。
2. React 告警列表及详情。
3. 单进程 LangGraph 与模拟工具。
4. checkpoint、暂停和恢复。
5. Celery、Redis 和 SSE。
6. Dify 知识库。
7. 可靠性、监控和测试。
8. pgvector 检索及 RAG 评测。

每一步都应保留可运行状态，并通过自动化测试或明确的手工验收脚本验证。

## 7. 演示脚本目标

最终求职演示应覆盖：

1. 提交一条 CPU 告警。
2. 展示四个工具并发运行及其中一个工具降级。
3. 展示带来源证据的诊断报告。
4. 在人工确认节点停止 Worker 并重新启动。
5. 批准后从 checkpoint 恢复并生成案例。
6. 重复提交相同告警，证明幂等生效。
7. 在知识问答中检索刚生成的案例。
8. 打开 Grafana 查看节点耗时、失败率和模型调用指标。
